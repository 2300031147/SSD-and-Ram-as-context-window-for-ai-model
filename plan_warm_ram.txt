Actually, the user expects that the server "thinks all this was space i can use to fill".
When starting llama-cli, the user specifies context size with `-c N`. The KV cache reserves `N` tokens in VRAM by default. If it doesn't fit, `llama.cpp` will usually fallback to RAM (using unified memory or just allocating on CPU backend). But `llama_kv_tiered_manager` allows explicitly moving blocks that don't fit into a swap file.
If the user wants RAM to be an explicit tier, we can add a new parameter `--kv-swap-ram-size` or dynamically allocate WARM_RAM buffers in system RAM up to a certain limit or until system memory pressure is high.
